# ІЧ-пульт для Лілки

Застосунок на Lua, який перетворює [Лілку](https://lilka.dev) на універсальний пульт. Вміє вивчати команди з будь-якого побутового пульта і потім надсилати їх сам.

## Що вміє

- зберігати кілька пристроїв — телевізор, світильник, підсилювач
- вивчати команди з чужого пульта і давати їм зрозумілі назви
- надсилати команди, з автоповтором при утриманні кнопки
- тримати все у звичайних текстових файлах, які легко правити на комп'ютері

Підтримується протокол **NEC** — це приблизно 80% побутової техніки. Кондиціонери поки не підтримуються: у них інші протоколи, значно складніші.

## Що потрібно зібрати

Потрібен простий ІЧ-модуль на роз'єм розширення. Схема і перелік деталей — у [IR.md від vaddieg](https://github.com/vaddieg/lilka-apps/blob/main/hardware/IR.md).

**Деталі:**

| Що | Скільки | Навіщо |
|---|---|---|
| ІЧ-світлодіод 940 нм (TSAL6400) | 1 | передавач |
| ІЧ-приймач TSOP4838 або VS1838B | 1 | приймач |
| Транзистор NPN 2N2222 | 1 | підсилює струм світлодіода |
| Резистор 22 Ом | 1 | обмежує струм світлодіода |
| Резистор 1 кОм | 1 | захищає пін Лілки |
| Макетна плата 20×80 мм | 1 | |
| Гребінка-лінійка на 12 контактів | 1 | |

**Підключення до роз'єму J2:**

| Контакт | Пін Лілки | Куди |
|---|---|---|
| 1 | GND | емітер транзистора |
| 2 | 3V3 | резистор 22 Ом → анод світлодіода |
| 7 | GPIO21 | резистор 1 кОм → база транзистора |
| 8 | GPIO14 | вихід приймача |
| 11 | 3V3 | живлення приймача |
| 12 | GND | земля приймача |

Катод світлодіода йде на колектор транзистора.

Приймач можна підключати напряму, без обв'язки. Світлодіод **не можна** вмикати в пін без транзистора й резистора — згорить пін.

## Встановлення

Скопіюй на SD-карту, в одну теку, чотири файли:

```
remote.lua     сам застосунок
menu.lua       інтерфейс
nec.lua        протокол
svitlo.txt     приклад пристрою (можна видалити)
```

Запускай `remote.lua` через файловий менеджер Кейри.

## Як користуватися

Керування скрізь однакове:

- **стрілки** — вибір
- **A** — дія
- **B** — назад
- **C** — меню

### Додати пристрій

`C` → «Новий пристрій» → ввести назву на екранній клавіатурі.

### Вивчити команди

Відкрити пристрій → `C` → «Вивчити команди». Далі просто натискати кнопки на справжньому пульті: після кожної з'явиться клавіатура, щоб ввести назву. Виходить конвеєром, десяток команд знімається за хвилину.

Угорі праворуч видно стан приймача. Якщо написано «приймач не бачу» — перевір підключення.

### Надсилати

Відкрити пристрій, обрати команду, натиснути `A`. Якщо тримати `A` — команда повторюватиметься, як на справжньому пульті. Зручно для гучності й яскравості.

### Перевірити передавач

`C` → «Тест передавача». Світлодіод блиматиме раз на секунду. Побачити це можна **фронтальною** камерою телефону — у задніх камер стоїть ІЧ-фільтр.

## Формат файлів

Кожен пристрій — окремий текстовий файл у корені SD-карти. Назва файлу довільна.

```
name: Світильник
protocol: NEC
address: 0xA0

Увімкнути            0x13
Вимкнути             0x1A
Яскравіше            0x59
```

Застосунок упізнає свої файли за рядком `address:`, тому інші txt на картці не чіпаються.

Такий файл можна написати руками, якщо коди вже відомі. Велика відкрита база кодів побутової техніки — [irdb](https://github.com/probonopd/irdb): там CSV, де `device` це адреса, а `function` — команда, обидва в десятковій системі.

## Як це працює

Три файли, кожен зі своєю роботою:

```
remote.lua   екрани, робота з пінами, читання й запис файлів
menu.lua     малює списки й меню, показує клавіатуру
nec.lua      перетворює код у послідовність спалахів і навпаки
```

Ключова ідея: `remote.lua` і `nec.lua` спілкуються **списками мікросекунд**. Залізо не знає, що таке NEC, а протокол не знає про піни. Завдяки цьому новий протокол додається одним файлом:

```lua
return {
    name = "Sony",
    carrier = 40000,
    encode = function(address, command) ... end,
    decode = function(edges) ... end,
}
```

і одним рядком у реєстрі на початку `remote.lua`.

`menu.lua` ні про що з цього не знає взагалі — його можна брати в будь-який інший застосунок для Лілки.

## Технічні подробиці

У Lua немає способу зачекати 560 мікросекунд: `util.sleep` працює з кроком в мілісекунду. Тому при старті застосунок калібрує порожній цикл — заміряє, скільки обертів припадає на мікросекунду, — і далі відмірює час обертами. Це точніше за звірку з годинником, бо `util.time()` з часом роботи грубішає.

Несучу 38 кГц генерує апаратний PWM, а програма лише вмикає й вимикає її.

## Відомі обмеження

- лише NEC; кондиціонери й інша складна техніка не підтримуються
- дальність залежить від резистора: з 22 Ом це 7–8 метрів, зі 100 Ом — метр-півтора
- вивчати можна тільки те, що працює на 38 кГц; для 36 і 40 кГц приймач ловитиме гірше
